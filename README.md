# wnsm.store

手机渠道报价网站，自动爬取八方报价单（lzbftx.vip），C 端看零售价、B 端同行看批发价，价格全部在服务端计算、原始成本价不下发。

**业务边界（当前定位）**：官网、微信小程序、微信公众号只用于让客户了解产品，做报价展示与咨询留资，**不提供线上下单、购物车、在线收款与支付功能**；三端关于页统一展示个人微信（兰州蜗牛数码）二维码、昵称与电话。成交在线下门店或微信私聊完成，价格、库存、保修、发票、付款方式等交易条件以电话/微信当面确认为准。抖音、快手、小红书只做功能性分类短视频引流，视频号只做展示获客；这些平台不开店、不做直播带货与站内成交，全链路不在线收款。用户路径固定为：短视频公域 → 公众号 / 小程序 / 官网展示承接 → 个人微信（兰州蜗牛数码）对接。

## 技术栈

- 前端：纯 HTML/CSS/JS（移动端优先）
- 后端：Cloudflare Pages Functions（无独立服务器，按请求运行）
- 数据库：Cloudflare D1（SQLite）
- 部署：Cloudflare Pages + GitHub Actions 自动化
- 数据：crawler.js 每日定时爬取八方报价单并生成 data.json

## 账号与价格分级

| 身份 | 注册 | 看到的价格 |
|---|---|---|
| 未登录 | — | 不显示价格，引导登录 |
| C 端个人客户 | 注册即通过 | 零售价 = 八方公开价 + 阶梯加价 |
| B 端同行·审核中 | 提交门店/联系人/执照 | 暂看零售价，标“审核中” |
| B 端同行·已通过 | 管理员审核 | 批发价 = 八方公开价 − 30 |
| 管理员 | 数据库内置 | 进入 /admin.html 审核同行 |

零售价阶梯：公开价 <2000 加 200；2000–5000 加 300；5000–10000 加 500；≥10000 加 800。
缺货（tags 含“缺货”或价格 <100）显示“缺货/待报价”，无价格。

### SKU 底价保护（防止亏本出货）

后台 `/admin.html` →「底价管理」可配置，规则缓存在服务端、改后约 1 分钟生效：

- **全局每台毛利** `b_margin`（默认 50）：B 端兜底价 = 八方会员价（公开价−80）+ 每台毛利。
- **单条规则**按 产品 id（精确） / 型号 model（精确） / 名称关键词（包含一批）匹配，优先级 id > model > name，可填：
  - 成本价 `cost`：你的真实拿货价。保证 **B 端 ≥ 成本 + 毛利**、**C 端 ≥ 成本 + 100**；
  - 硬底价 `floor`：B 端绝不低于此；
  - 固定价 `fixed`：直接作为 B 端批发价（最高优先级）。
- 支持 CSV 批量导入（`类型,匹配值,成本,硬底价,固定价,备注`），并可按型号搜索预览公开价/会员价/成本/底价/最终售价。

**批量录入工具**：`node build-cost-template.mjs` 依据当前 data.json 生成 9 个品牌清单（`成本_01_苹果.csv` … `成本_09_其他品牌.csv`，平板单独成表），只含在库、公开价≥5000 的手机+平板，按产品 id 精确匹配。文件内同机型按运行内存/存储聚拢，自动区分典藏版/先锋版/柔光版等版本变体（如 MateX7 普通版与典藏版分组），同颜色的「激活/原封」相邻（贵机型排在前），备注标注渠道【激活】/【原封】/【官网】/【国补】与公开价。成本表已在 `.gitignore` 忽略（含真实拿货价，禁止提交）。只对**拿货价高于八方会员价（公开价−80）**的机型填「成本」，删掉其余空行，再把内容粘到后台「批量导入」；拿货价更低的机型无需填，全局毛利已自动让你赚得更多。



### 安全机制

- 原始 `data.json` 含八方成本价：`functions/data.json.js` 对所有外部请求返回 403；函数内部通过 `env.ASSETS.fetch('/data.json')` 读取（5 分钟内存缓存）。
- `/api/products` 只返回按身份计算后的 `displayPrice`，永不下发原始 `price`、`shopId`、`sourceId`。
- 密码：PBKDF2-SHA256、10 万次迭代、每用户 16 字节随机 salt，不存明文。
- 会话：32 字节随机 token 存 D1，经 `httpOnly + Secure + SameSite=Lax` Cookie 下发（名 `wnsm_session`，30 天）。

## 本地复现 / 重建

```bash
# 1. 创建 D1 数据库
npx wrangler d1 create wnsm-db
#   将返回的 database_id 填入 wrangler.toml 的 [[d1_databases]]

# 2. 建表（远程）
npx wrangler d1 execute wnsm-db --remote --file schema.sql

# 3. 本地部署
export CLOUDFLARE_API_TOKEN=...
export CLOUDFLARE_ACCOUNT_ID=...
npx wrangler pages deploy . --project-name=wnsm-store --branch=main --commit-dirty=true
```

管理员账户需直接写入 D1（密码哈希算法须与 functions/_lib/auth.js 一致：PBKDF2-SHA256、10 万次、salt 拼接）。

## 定时爬虫

- push 触发 deploy.yml 自动部署。

## 全域一体化（小程序 / 公众号 / 视频号 / 抖音 / 快手 / 小红书）

详见 `docs/全域一体化运营方案与中台原型.html` 与 `docs/一体化上线操作手册.md`。

**分工定位**：微信小程序、微信公众号、官网 `www.wnsm.store` 是承接阵地，只用于让客户了解产品，做报价展示、会员分级价与咨询留资；视频号只做展示获客，抖音、快手、小红书只做功能性分类短视频引流。这些平台不开店、不做直播带货、不做站内成交，全链路不在线收款。

**分层跳转链路（合规可行口径）**：
- **视频号 → 公众号 / 小程序**：同主体绑定后走主页官方入口直接跳转；官网经公众号菜单中转，视频号不直挂官网外链，也不展示个人微信二维码。
- **公众号 ↔ 小程序 ↔ 官网**：菜单、图文卡片、web-view 微信内互通；三端关于页统一展示个人微信（兰州蜗牛数码）二维码、昵称与电话 17361593016。
- **抖音 / 快手 / 小红书 → 承接阵地**：平台规则禁止在视频、简介、评论、私信直接挂公众号、小程序、官网、个人微信链接或二维码；只能使用官方联系方式 / 留资组件，回流靠官方电话沟通或用户主动搜索"兰州蜗牛数码"进入承接阵地。

**短视频两条生产线**：
- 轨道 A · 素材剪辑：用户提供原始视频素材，我方剪辑、配字幕/封面/标题/话题，输出各平台适配画幅。
- 轨道 B · 型号生成视频：用户给出产品型号与功能点，由 Seedance 2.5 按品牌/机型/功能分类脚本生成短视频，发布前人工核对机型、参数、价格与保修口径，画面与实物一致。

- `miniprogram/`：微信小程序原生工程，复用本仓库同一套 API 与 D1 用户体系，微信开发者工具导入即可预览。
- 新增后端接口：`/api/wechat-login`、`/api/wechat-bind`、`/api/channel-track`、`/api/wx-jsapi-signature`；`/api/login`、`/api/register`、`/api/me` 响应补充小程序端使用的 `token`。
- 新增表：`external_identities`（各端 openid/unionid 与手机号账号映射）、`channel_tracks`（渠道归因）。
- 上线前需在 Cloudflare Pages 配置 `WX_MP_APPID / WX_MP_SECRET / WX_OA_APPID / WX_OA_SECRET` 环境变量，并完成小程序、服务号、视频号的组织主体（个体工商户或企业）注册、备案与同主体绑定。
