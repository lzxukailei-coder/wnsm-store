wnsm.store 全域一体化运营中台 原型

一套商品库、一套会员体系，
分发到 7 个触达渠道统一运营

在已上线的 wnsm.store（Cloudflare Pages + Functions + D1，手机渠道报价，C/B 分级定价）基础上，把微信公众号、微信小程序、微信视频号、个人微信、抖音、快手、小红书纳入同一套后台与数据统一运营：商品与价格只录一次，用户身份跨端打通，咨询线索按渠道回溯。定位边界：小程序、公众号、官网只用于让客户了解产品，仅做报价展示与咨询留资，不做线上下单与在线收款；抖音、快手、小红书只做功能性分类短视频引流，视频号只做展示获客，不在任何平台开店、不做直播带货与站内成交。短视频两条生产线：用户提供原始素材由我方剪辑；用户给出产品型号后由 Seedance 2.5 生成视频，人工审核合规再发布。用户路径固定为：短视频公域 → 公众号 / 小程序 / 官网展示承接 → 个人微信（兰州蜗牛数码）对接；抖音、快手、小红书受平台规则限制，只能走官方合规入口，不能直接挂微信、官网或小程序链接。本页是方案说明 + 中台看板可交互原型，深色数据中台风格。

总体架构：一个中台，三层分发

自上而下：渠道触点 → 统一中台（已有网站 + 本次新增接口）→ 数据源。用户不管从哪个端进来，落到的都是同一张 users 表和同一份 products 目录。

必须先认清的边界（不要被"一键全平台打通"的说法带偏）：
  • 微信内部能深度打通：公众号、小程序、视频号在同一主体、接入微信开放平台后可用 unionid 识别同一用户，菜单/图文/客服互相跳转；三者只做展示与咨询对接，不接在线支付、不开微信小店。
  • 抖音、快手、小红书是封闭围墙：平台规则禁止在站内引导跳到外部网站、微信或第三方小程序。按当前定位，这些平台只做功能性分类短视频曝光引流，不开通小店、不做直播带货、不做站内成交闭环；商品与用户数据无法像微信那样直接写入你的 D1，只能靠导出报表、平台允许范围内的合规留资、渠道参数做弱关联。
  • 因此"一体"的真实含义是：一套商品/内容/会员中台 + 微信三端展示互通 + 外部平台合规引流后回流咨询线索，而不是七个平台共用一个后台账号体系，更不是把成交搬到线上。
